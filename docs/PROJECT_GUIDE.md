# Beginner guide to this portfolio

This guide explains where the existing pieces live and how to make common updates without changing the visual effects or accidentally removing a section.

## Folder map

```text
hammad-wani-portfolio/
├── docs/                 Guides, reference notes, and design previews
├── public/               Files served as-is, including the downloadable résumé PDF
├── scripts/              Helper scripts for generating project assets
├── src/
│   ├── assets/           Images imported by the app
│   ├── components/       Page sections and reusable interface pieces
│   ├── data/             Personal details, skills, experience, and projects
│   ├── main.tsx          App entry point; connects React, Site, and CSS
│   └── styles.css        Site-wide layout, typography, colors, and responsive rules
├── index.html            Browser title, description, and root element
├── package.json          Run commands and dependency list
└── vite.config.ts        Vite development/build configuration
```

`node_modules/` contains installed packages and can be recreated with `npm install`. `dist/` is generated by `npm run build`; it is the publish-ready output. Neither is where you edit the portfolio.

## Where personal content lives

### Your profile and project information

Open [`src/data/site.ts`](../src/data/site.ts). This is the content file to use first when updating your name, role, email, location, links, biography, skills, education, experience, or project descriptions. Project entries and their tags are kept together there so the home project rail and archive stay in sync.

### Images

Put imported images in `src/assets/`, then reference them from the content data. Files placed in `public/` are served directly from the site root; the résumé PDF is an example. Keep the résumé at `public/resume-hammad-wani.pdf` unless you also update its download links.

### Résumé source

The résumé page is built from the same profile, skills, education, experience, and projects in `src/data/site.ts`. The PDF generator is `scripts/generate_resume_pdf.py`; its output goes into `public/`.

## Where each page and section lives

The current app keeps the page components together in [`src/components/Site.tsx`](../src/components/Site.tsx). Use VS Code’s **Find** (`⌘F` on Mac, `Ctrl+F` on Windows/Linux) and search the names below to jump to a section.

| Search for | What it controls |
| --- | --- |
| `function Header` | Sticky top navigation and links to About, Projects, Home, and Contact |
| `function Hero` | First screen, intro text, visual orb, and oversized name/headline |
| `function FocusBand` | Three-word ticker between the hero and About |
| `function AboutSection` | About copy and profile résumé links |
| `function SkillsSection` | Skills groups and expandable skill tiles |
| `function ProjectsSection` | Selected projects and the horizontal project rail |
| `function ProjectsIndex` | Searchable full project archive at `/projects` |
| `function ContactSection` | Contact details and message form |
| `function Footer` | Bottom-of-page links and back-to-top link |
| `function ResumePage` | On-site résumé page, print, and PDF download controls |
| `function CaseStudyPage` | MCI research case-study route |
| `function Site` | Chooses which page to show for the current URL |

Reusable visual features are also in `Site.tsx`: `DitherOrb`, `PixelImage`, `FeaturedRail`, `ScrollWords`, `ProximityHeading`, and `ResearchDiagram`.

## Styling and layout

Open [`src/styles.css`](../src/styles.css) for the site’s visual design. It contains the global styles and responsive rules for desktop, tablet, and mobile. Search for a class name from the relevant component (for example `hero`, `about-section`, `skills-section`, or `projects-rail`) to find its styles. Keep related responsive overrides with the existing media-query sections where possible.

`src/main.tsx` is the small startup file. It mounts the site and loads the stylesheet; most content edits should not require changing it.

## Safe editing routine

1. Make content edits in `src/data/site.ts` first.
2. Use `Site.tsx` only when adding/removing a section or changing its behavior.
3. Use `styles.css` when adjusting how that section looks.
4. Run `npm run dev` and inspect the page in a browser.
5. Run `npm run build` before publishing. A successful build confirms TypeScript checks and generates `dist/`.

When adding a project, add it to the existing project list in `src/data/site.ts` and provide an image/visual, summary, technologies, and any repository or live-site link. The site uses that shared list to render the project rail and archive.
